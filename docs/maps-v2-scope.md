Продуктовые решения по новому проекту на основе этого прототипа.
Приняты 2026-07-08.

## Продукт

Публичный веб-сервис для создания интерактивных карт: открытая регистрация,
незнакомые люди создают свои карты, делятся ими и публикуют. Прототип служит
референсом; код переносится выборочно, демо-слои не переносятся.

## Ключевое архитектурное решение: источник ≠ слой ≠ карта

Три сущности вместо иерархии прототипа (Workspace → Layer → Feature):

- **Источник данных** — самостоятельная сущность со своим реестром.
  Тип (нарисованные фичи, загруженный файл, внешний API, GeoJSON-URL),
  endpoint, ключи, настройки обновления.
- **Слой** — визуализация поверх источника: цвет, стиль, кластеризация,
  тип отображения. Один источник может питать несколько слоёв.
- **Карта** — композиция слоёв + стиль подложки + доступы.

Данные отделены от представления (как в Felt / Kepler.gl). Модель данных
проектируется заново; из прототипа переносятся Mapbox-примитивы рендеринга
(mapPrimitives, подход layerRegistry).

## Стек

- **Рендеринг:** Mapbox GL (решение: остаёмся, на MapLibre не переходим).
- **Backend:** Supabase — Postgres + PostGIS, Auth, RLS, Storage.
  Ключи чувствительных API проксируются через Edge Functions.
- **Frontend:** React + Vite + Zustand, добавляются TanStack Query и роутер.

## MVP — входит

1. **Auth:** Google OAuth (единственный способ входа).
2. **Галерея карт:** список своих и расшаренных карт с превью
   (Mapbox Static Images API), создание / удаление / переименование.
3. **Редактор:**
   - рисование (маркеры, текст, линии, полигоны) — механизм переосмыслить,
     архитектуру заложить с запасом, не копировать прототип;
   - импорт файлов CSV / GeoJSON / KML;
   - поиск мест (Mapbox Geocoding) с добавлением результата как маркера.
4. **Источники данных:** реестр источников + 2–3 готовых коннектора на старт
   (какие именно — решается на этапе 4) + произвольный GeoJSON-URL.
5. **Шаринг:** приглашение по email с ролями viewer / editor;
   публичная ссылка без логина (режим просмотра).
6. **Лента «Исследовать»:** публичные карты всех пользователей,
   с флагом featured для ручной модерации с первого дня.
7. **Квоты:** лимиты на пользователя (число карт, фич, размер импорта)
   заложены в схему сразу. Продукт пока бесплатный, без оплаты.

## Не входит в MVP

- Демо-слои прототипа (самолёты, корабли, МКС, кабели и т.д.) — не переносить.
- Realtime-совместное редактирование (курсоры, live-синк) — позже,
  на Supabase Realtime.
- Платные планы / Stripe — когда появится спрос.
- Произвольные API-коннекторы с маппингом полей — только каталог + GeoJSON-URL.
- Мобильное приложение.

## Этапы

1. Схема БД + RLS-политики + auth + CRUD карт.
2. Галерея + лента «Исследовать».
3. Редактор: рисование и слои.
4. Источники данных + импорт файлов.
5. Шаринг + публичные страницы.
6. Квоты, превью, полировка.

Рабочий MVP — после этапов 3–4. Каждый этап доводится до проверенного
состояния (запуск, прогон флоу; RLS-политики покрываются тестами обязательно —
дыра в шаринге означает утечку чужих карт).

## Открытые вопросы

- Название проекта / репозитория.
- Какие 2–3 коннектора взять первыми (решение на этапе 4).
- Гранулярность сохранения фич при рисовании (per-feature vs batch +
  debounce) — решить на этапе 3, Mapbox Draw генерирует много апдейтов.
